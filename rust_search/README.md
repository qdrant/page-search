Site search, fast

### Preparation

This version of the search uses a local model. So you need the model in the working path of the service. To get the ONNX file, run

```bash
curl -L -o all-MiniLM-L6-v2.onnx https://huggingface.co/optimum/all-MiniLM-L6-v2/resolve/main/model.onnx
```

in the `rust_search` directory.

Before we run anything, we need the URL and possibly API key. All binaries take these from environment variables. Set them as follows:

```bash
export QDRANT_URL=#<your Qdrant address including port>
export QDRANT_API_KEY=#<your Qdrant API key as needed>
```

Since the embeddings are the same as with the python search, you can easily re-use its collection. Alternatively you can run the `setup_collection` binary, after running `crawl` (see the above directory).

We also need to set up a prefix cache collection for the recommender function. To do that, run

```bash
cargo run --release --bin index_prefix
```

Running the service can be done via

```bash
export SERVICE_URL=#<the URL the service will be listening to>
cargo run --release --bin service
```

### Redirects on the `/md/` mirror

A `/md/` request the mirror has no document for is checked against
[`qdrant.tech/redirects.txt`](https://qdrant.tech/redirects.txt) before it 404s,
so paths qdrant.tech has moved redirect here too. That file is generated by
`automation/generate-redirects-table.py` in `landing_page` and merges the
`_redirects` file, the `netlify.toml` rules and Hugo's `aliases:` front matter
into one first-match-wins table. It is the single owner of those rules — never
hand-maintain a rule list in this repo, or the two halves will diverge.

At startup the service reads the copy on disk — local and instant — and fetches
the live table in the background, so **boot never waits on qdrant.tech**. A cold
start with no cache has a short window where `/md/` misses 404, which is the
behaviour this replaces, so nothing regresses while it closes. The table then
refreshes hourly, because a landing-page deploy does not restart this service. A
failed fetch keeps the table already loaded, or falls back to the cached copy;
with neither, `/md/` misses 404 as they did before.

The resolved cache path is logged at startup and probed for writability, because
an unwritable path means the disk fallback silently never exists.

| Variable | Default | Purpose |
| --- | --- | --- |
| `REDIRECTS_URL` | `https://qdrant.tech/redirects.txt` | Where to fetch the table. Point it at a local copy to develop offline. |
| `REDIRECTS_CACHE_PATH` | `$TMPDIR/qdrant-redirects.txt` | On-disk copy used when a fetch fails. A relative value is resolved against the working directory. |
| `REDIRECTS_REFRESH_SECS` | `3600` | Refresh interval. |

The cross-host agreement test needs both hosts live and is ignored by default:

```bash
cargo test --test cross_host_agreement -- --ignored --nocapture
```
